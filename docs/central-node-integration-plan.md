# Relay Panel 子站接入总站升级方案

## 1. 文档目的

本文定义 Relay Panel 子站为接入“总站”必须完成的升级。目标是让总站可以安全、稳定地读取每台子站的运行状态和线路摘要，而不是让总站直接获得子站的管理员权限。

本文只讨论“子站程序”需要做的改造。总站页面、总站部署、批量升级和回退界面另行实现。

## 2. 已确认的边界

### 2.1 总站负责什么

- 保存子站名称、管理地址、服务器有效期提醒和接入凭据。
- 定时读取子站的可用性、Xray 状态、线路数量、异常数量、累计流量、延迟和面板版本。
- 显示绿、黄、红灯。
- 子站服务器有效期只作为总站的手工提醒；总站不会将这个日期写回子站，也不会据此停止子站流量。
- 后续可增加指定版本升级、分批升级、健康检查和回退，但本次不开放远程写操作。

### 2.2 子站负责什么

- 继续独立运行现有 RP 面板和现有线路有效期逻辑。
- 向总站提供受限的只读管理接口。
- 生成、撤销总站专用令牌。
- 不保存总站管理员密码、SSH 密码或总站会话。
- 不因总站离线、总站服务器到期或总站轮询失败而影响任何线路。

### 2.3 明确不做的事情

- 不把子站面板页面通过 iframe 或公网反向代理暴露到总站浏览器。
- 不允许总站执行任意 Shell 命令。
- 不让总站使用子站的网页登录密码。
- 不复用现有“全权限 API Token”作为正式总站凭据。
- 不把子站服务器有效期、线路有效期混为同一套控制逻辑。

## 3. 当前代码盘点

本地子站版本为 `v2.0.17`。已有代码已经提供以下基础能力：

| 能力 | 当前状态 | 说明 |
| --- | --- | --- |
| `GET /panel/api/server/status` | 已有 | 返回面板、系统和 Xray 状态。 |
| `GET /panel/api/lines` | 已有 | 返回线路列表。 |
| `GET /panel/api/lines/metrics` | 已有 | 返回线路累计流量与检测指标。 |
| `GET /panel/api/server/getPanelUpdateInfo` | 已有 | 返回面板版本信息。 |
| Bearer API Token 鉴权 | 已有 | 现有令牌可访问整个 `/panel/api/*`，权限过大。 |
| Token 后端管理接口 | 已有 | 可创建、禁用、删除，但当前 RP 页面没有面向总站的接入入口。 |

因此，不能把“已有普通接口”直接当作正式子站协议。最大问题是权限：总站只需读取摘要，但现有 API Token 实际上可调用线路创建、删除、应用、证书等管理接口。

## 4. 目标版本与兼容规则

### 4.1 版本

本次子站升级发布为 `v2.0.18`。

发布前必须同步修改：

1. `internal/config/version` 为 `2.0.18`。
2. 面板内显示的版本号。
3. Git 提交和 CI。
4. CI 成功后创建并推送精确匹配的 `v2.0.18` 标签。

未同时满足“代码版本号为 `2.0.18`”和“远程 Git 标签为 `v2.0.18`”时，不视为可供总站接入的正式版本。

### 4.2 协议兼容

- `v2.0.18` 是总站接入的最低子站版本。
- 总站首先读取能力接口；协议版本不支持或低于最低版本时，显示红灯和明确错误“子站版本不支持总站接入”。
- `v2.0.17` 及更早版本不允许通过普通全权限 API Token 伪装接入。
- 后续协议字段只能新增，不能删除或改变已有字段含义。

## 5. 安全模型

### 5.1 新增令牌类型

新增独立的“总站只读令牌”，与现有全权限 API Token 分开保存和校验。

建议数据模型：

```text
central_access_tokens
  id
  name
  token_hash
  enabled
  created_at
  last_used_at
  last_used_ip
  revoked_at
```

规则：

- 原始令牌使用高强度随机值生成，长度至少 48 个随机字符。
- 数据库只保存 SHA-256 哈希，永不保存明文。
- 明文仅在创建成功的响应中显示一次；刷新页面后不能重新查看。
- 每台子站建议只保留一个启用的总站令牌；重新生成时先创建新令牌，确认总站连通后再撤销旧令牌。
- 禁用或删除后立即失效，无需重启子站。
- 令牌不能登录网页，也不能调用现有 `/panel/api/*` 的普通管理端点。

### 5.2 最小权限范围

总站只读令牌仅允许访问：

```text
GET /panel/api/central/capabilities
GET /panel/api/central/summary
GET /panel/api/central/lines
```

其他路径一律返回 `403`，包括但不限于：

- 线路新增、编辑、删除、保存并应用。
- Xray 重启、停止、配置导入导出。
- 证书读取或上传。
- 用户、订阅、节点、数据库和系统设置。
- 现有普通 `/panel/api/server/*` 与 `/panel/api/setting/*` 管理接口。

### 5.3 传输安全

- 正式接入只接受 HTTPS 子站地址。
- 总站必须验证子站证书，不能提供“跳过证书校验”选项。
- 对公网子站建议使用域名和有效证书；不建议将面板管理端口直接暴露给所有来源。
- 本次只读阶段不强制 mTLS；后续有写操作时，再为升级控制使用独立 mTLS 或独立升级令牌，不能扩大只读令牌权限。

## 6. 新增 API 协议

所有响应沿用子站当前信封格式：

```json
{"success": true, "msg": "", "obj": {}}
```

错误响应：

```json
{"success": false, "msg": "..."}
```

### 6.1 能力接口

```text
GET /panel/api/central/capabilities
Authorization: Bearer <总站只读令牌>
```

作用：总站登记前先确认该子站是受支持的 RP 子站，而非误填的普通地址。

成功响应固定包含：

```json
{
  "success": true,
  "obj": {
    "product": "relay-panel",
    "role": "node",
    "centralProtocolVersion": 1,
    "panelVersion": "2.0.18",
    "nodeId": "稳定且不含地址的随机节点标识",
    "readOnly": true,
    "features": ["summary", "lines"]
  }
}
```

校验规则：

- `product` 必须为 `relay-panel`。
- `role` 必须为 `node`。
- `centralProtocolVersion` 必须等于 `1`。
- `readOnly` 必须为 `true`。
- `nodeId` 在子站安装后稳定不变；总站将其与本地记录绑定，防止同一地址被替换为另一台机器后静默混淆。

### 6.2 子站摘要接口

```text
GET /panel/api/central/summary
Authorization: Bearer <总站只读令牌>
```

作用：替代总站轮询多条普通子站接口。一次请求获得总站首页所需的全部摘要。

建议响应：

```json
{
  "success": true,
  "obj": {
    "centralProtocolVersion": 1,
    "nodeId": "node_...",
    "panelVersion": "2.0.18",
    "sampledAt": "2026-08-04T12:00:00Z",
    "xray": {
      "state": "running",
      "error": ""
    },
    "lines": {
      "total": 2,
      "healthy": 2,
      "abnormal": 0,
      "expired": 0
    },
    "traffic": {
      "totalBytes": 123456789
    }
  }
}
```

字段定义：

| 字段 | 含义 | 规则 |
| --- | --- | --- |
| `sampledAt` | 子站生成本次摘要的 UTC 时间 | RFC3339。 |
| `xray.state` | `running`、`stopped`、`error`、`unknown` | 不得用布尔值替代。 |
| `xray.error` | Xray 异常原因 | 正常时为空；不得返回敏感配置。 |
| `lines.total` | 子站所有线路数 | 包含到期线路。 |
| `lines.healthy` | 当前正常线路数 | 由子站既有线路状态计算。 |
| `lines.abnormal` | 非到期但异常的线路数 | 用于总站红灯判断。 |
| `lines.expired` | 已到期并被子站停用的线路数 | 仅显示，不改变总站的服务器有效期提醒。 |
| `traffic.totalBytes` | 全部线路累计流量之和 | 单位是字节，必须是累计值，不是实时速度。 |

摘要接口不得返回：线路 UUID、Reality 私钥、证书内容、住宅代理账号密码、订阅令牌、客户端列表、系统路径或完整 Xray 配置。

### 6.3 线路只读列表接口

```text
GET /panel/api/central/lines
Authorization: Bearer <总站只读令牌>
```

作用：仅在用户从总站点击某台服务器名称进入只读详情页时调用。总站首页不应对每台服务器反复拉取完整线路详情。

每条线路只允许返回：

```json
{
  "id": 12,
  "name": "Cloudflare 主线路",
  "type": "cloudflare",
  "status": "normal",
  "validFrom": "2026-08-01",
  "validUntil": "",
  "manualReenableRequired": false,
  "totalTraffic": 123456,
  "inboundLatencyMs": 45,
  "outboundLatencyMs": 180,
  "lastCheckedAt": "2026-08-04T12:00:00Z",
  "lastError": ""
}
```

禁止返回入口域名、端口、WS 路径、SNI、UUID、密码、私钥、公钥、订阅地址、二维码或完整分享链接。

## 7. 子站管理页面改造

### 7.1 入口位置

在子站“设置”页面增加“总站接入”区块，放在现有安全相关设置附近，不新建独立导航页。

页面内容：

```text
总站接入
  当前模式：子站
  协议版本：1
  本站标识：node_...                     [复制]
  推荐管理地址：https://panel.example.com:2053/随机路径
  接入令牌：未配置 / 已启用 / 已禁用
  最后使用：时间、来源 IP（没有则显示“尚未使用”）

  [生成总站只读令牌]
  [禁用令牌] [删除令牌]
```

### 7.2 生成流程

1. 管理员点击“生成总站只读令牌”。
2. 前端显示确认弹窗，明确该令牌只允许总站读取状态，且只显示一次。
3. 后端生成令牌，保存哈希。
4. 后端返回一次明文令牌。
5. 前端在不可自动关闭的确认框中显示令牌，并提供复制按钮。
6. 管理员将令牌粘贴到总站“添加服务器”表单。
7. 关闭确认框后，子站只能显示“已启用”，不可再次显示明文。

### 7.3 撤销与更换

- “禁用”：立即停止总站读取，保留记录，方便误操作后恢复。
- “删除”：不可恢复，当前总站下次心跳显示红灯。
- “轮换”：先生成新令牌，在总站更新并探测成功后，再删除旧令牌。页面需明确提示该顺序。

## 8. 后端实现步骤

### 8.1 数据库迁移

1. 新增 `central_access_tokens` 表或等价模型。
2. 为 `token_hash`、`enabled` 和 `created_at` 建立必要索引。
3. 迁移必须可重复执行，已有用户数据库升级不能失败。
4. 不迁移、复制或转换旧的全权限 `api_tokens` 数据。
5. 为子站持久化生成稳定的 `nodeId`；首次升级生成一次，后续始终复用。

### 8.2 鉴权中间件

1. 在普通 `/panel/api` 鉴权之前或并行增加总站只读路由组。
2. 只接受 `Authorization: Bearer <token>`。
3. 将令牌哈希后匹配启用的总站令牌。
4. 匹配成功后设置专用上下文标记，例如 `central_read_only=true`。
5. 不设置普通管理员会话，不复用 `api_authed` 的全权限语义。
6. 非允许路径始终返回 `403`，不能因已有网页登录 Cookie 而放行总站专用路径的写操作。
7. 更新令牌 `last_used_at` 和 `last_used_ip` 时需限频，避免每次心跳造成频繁数据库写入。

### 8.3 汇总服务

1. 从既有 `ServerService.LastStatus()` 读取 Xray 状态。
2. 从既有线路服务读取线路及指标。
3. 在服务层计算 `total`、`healthy`、`abnormal`、`expired` 与 `totalBytes`。
4. 统一状态映射，避免总站自行猜测旧状态字符串。
5. 所有读取失败必须返回可区分的错误，不能把失败伪装成零值健康状态。
6. 日志只记录错误类别、节点令牌 ID 和请求 ID；严禁记录令牌明文或完整 Authorization 头。

### 8.4 路由

新增独立路由组：

```text
/panel/api/central/capabilities
/panel/api/central/summary
/panel/api/central/lines
```

这三个端点均为 `GET`，且只接受总站只读令牌。普通管理员网页登录后也可查看，但不能从这组路由触发写操作。

## 9. 总站对接顺序

必须按以下顺序上线，不能跳过：

1. 完成子站 `v2.0.18` 代码和测试。
2. 发布 Git `v2.0.18` 标签。
3. 在一台测试子站升级到 `v2.0.18`。
4. 在测试子站创建总站只读令牌。
5. 在总站录入该子站的 HTTPS 地址、端口、路径、服务器有效期提醒和只读令牌。
6. 总站先调用 `capabilities`；仅协议校验通过后才保存。
7. 总站调用 `summary` 并比对 `nodeId`；成功后显示绿、黄或红状态。
8. 用户点击服务器名称时，总站调用 `lines` 显示只读线路详情。
9. 连续运行至少 24 小时，观察心跳、令牌轮换和异常状态。
10. 验证通过后，再升级其他子站。

## 10. 状态灯计算约定

总站使用子站摘要和总站本地服务器有效期提醒计算：

| 优先级 | 条件 | 灯色 |
| --- | --- | --- |
| 1 | HTTPS、令牌、协议校验、摘要请求任一失败 | 红色 |
| 2 | `xray.state` 不为 `running` | 红色 |
| 3 | `lines.abnormal > 0` | 红色 |
| 4 | 本站服务器有效期提醒在 7 天内到期 | 黄色 |
| 5 | 以上均不满足 | 绿色 |

说明：

- 子站服务器到期由供应商处理，不由总站控制；子站失联后自然显示红灯。
- 子站内部线路到期由子站的既有严格停用逻辑处理；总站仅读取 `expired` 统计，不负责恢复或停止。
- 黄色只代表服务器续费提醒，不代表线路故障。

## 11. 测试清单

### 11.1 单元测试

- 生成的总站令牌只能以明文返回一次，数据库中没有明文。
- 启用、禁用、删除、轮换令牌的状态正确。
- 普通全权限 API Token 不得访问 `/panel/api/central/*`，除非明确兼容规则另行规定。
- 总站只读令牌访问普通 `/panel/api/lines/:id/delete`、`/apply`、`/server/restartXrayService` 时必须为 `403`。
- 无令牌、错误令牌、禁用令牌、删除令牌均被拒绝。
- `summary` 正确映射 Xray 的 `running`、`stopped`、`error` 状态。
- `summary` 正确统计正常、异常、到期线路和累计流量。
- `lines` 响应不含 UUID、密钥、证书、入口地址或订阅链接。
- `nodeId` 在重启和数据库迁移后保持不变。

### 11.2 集成测试

1. 使用 `httptest` 模拟总站，以只读令牌依次请求三个接口。
2. 验证返回均为既定信封格式。
3. 验证总站请求路径、Authorization 头和错误码。
4. 验证自签名或无效证书由总站拒绝。
5. 验证断网、超时、Xray 停止、单线路异常时总站能获得不同错误状态。
6. 轮换令牌后，旧令牌立即失败，新令牌成功。

### 11.3 人工验收

1. 子站设置页能创建、复制、禁用、删除总站只读令牌。
2. 令牌关闭弹窗后不能再次显示。
3. 总站录入错误地址、错误端口、错误路径、错误令牌时给出明确提示。
4. 总站录入正确资料后显示服务器名称、IP、有效期、延迟、累计流量、版本、线路数和异常数。
5. 停止子站 Xray 后总站在下一轮心跳显示红灯。
6. 把总站服务器有效期设为 7 天内后显示黄灯，但子站线路保持可用。
7. 使一条子站线路异常后总站显示红灯，并能在只读详情中看到不含敏感信息的错误摘要。

## 12. 发布与回退

### 12.1 发布前

- 清理无关未提交文件，特别是临时计划文档副本。
- 运行 Go 后端测试、前端检查和构建。
- 检查 API 文档和前端翻译。
- 检查 `internal/config/version` 与发布目标一致。

### 12.2 发布

1. 提交子站代码。
2. 推送 `main`。
3. 等待 CI 成功。
4. 创建并推送 `v2.0.18` 标签。
5. 先升级一台测试子站。
6. 通过总站接入和 24 小时观察后，再逐台升级生产子站。

### 12.3 回退

- 子站升级失败：使用现有 `relay-panel rollback` 回到本机保存的上一备份版本。
- 子站成功升级但总站协议有问题：先在总站禁用该节点，不影响子站现有线路；然后在子站回退。
- 禁止在回退前删除数据库迁移相关数据。新增表应保持向后兼容，旧版本忽略即可。
- 回退后总站应显示“协议不支持”或红灯，而不是错误地显示绿色。

## 13. 本次实施产物

子站 `v2.0.18` 实施完成时，至少应包含：

1. 总站只读令牌的数据模型、迁移、服务和审计。
2. 三个受限只读接口。
3. 设置页“总站接入”区块及中英文（及现有支持语言）翻译。
4. 协议数据结构和全面测试。
5. 更新后的 API 文档。
6. 与总站 `centralProtocolVersion=1` 的真实对接测试。

在这些产物完成之前，总站只能作为页面原型，不能接入真实子站。
